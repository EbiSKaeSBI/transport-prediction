# Предиктор изменений в графике движения городского транспорта (NDTP)

Система раннего предупреждения опозданий наземного транспорта: поток
телематрии NDTP → map-matching на нитку графика → ML-прогноз задержки в
горизонте 10–15 минут → алерты и BI-дашборд диспетчера.

## Запуск одной командой (Docker)

```bash
docker compose up -d --build
# полный контур с потоком исторических данных (реальный датасет train/):
docker compose --profile feed up -d --build
```

Первый запуск: сервис `plan-init` ~2 минуты собирает план-график из
`train/schedule.csv` в общий том, затем поднимаются backend и дашборд
(кэш образов — повторный старт за секунды). Через несколько секунд после
старта открыт дашборд: **http://localhost:8088**
(первые минуты поток разгоняется: `dataset_feed` сканирует датасет ~2 мин,
затем телеметрия идёт со скоростью реальной жизни, `--speed 1`).

| Сервис | Адрес | Что смотреть |
|---|---|---|
| Дашборд | http://localhost:8088 | карта сети, ТС, цвета риска, рельс инцидентов |
| Backend API | http://localhost:8080 | `/api/v1/routes`, `/api/v1/model`, WS `/ws/stream` |
| Swagger UI | http://localhost:8080/swagger | спецификация API; `/openapi.yaml` — машинночитаемая |
| Метрики | http://localhost:8080/metrics | latency инференса, глубина очереди, инциденты |
| ML-ядро | внутри сети `ml:8000` | `/healthz`, `/model/info`, `POST /predict/batch` |
| NDTP-вход | :9201 | gRPC/сокет-порт для эмулятора или плеера с хоста |

## Как подать поток

* **Вариант А (в комплекте):** `--profile feed` — сервис `feed` проигрывает
  `train/traffic.csv` (`scripts/dataset_feed.py`, stdlib-python) кадрами NDTP
  в `backend:9201`; план в общий том уже положил `plan-init`.
* **Вариант Б (официальный эмулятор):** распаковать
  `ndtp-telemetry-emulator.tar` и слать поток на `localhost:9201`
  (снаружи контейнеров порт проброшен; план генерирует `plan-init`,
  вручную: `python3 scripts/dataset_feed.py --generate-only --plan-out plan.csv --binding-out binding.csv`).
* **Вариант В (без потока):** backend работает с планом, но без телеметрии —
  дашборд честно показывает «нет свежей телеметрии»; при обрыве ML —
  деградация на baseline-правило без падения (требование ТЗ).

## Где прогнозы и алерты

* Дашборд: цвет каждой точки ТС и пройденного звена — зелёный < 60 с,
  жёлтый 60–120 с, красный ≥ 120 с прогноза отставания у цели (модель +
  парный P(опоздание)-классификатор, причины — из доминирующего признака).
* Карточка инцидента (правая колонка): ТС, прогнозируемое опоздание,
  P(опозд.), время, горизонт, участок «от какой остановки до какой», причина.
* WS-стрим `/ws/stream` — те же события в JSON (контракт в OpenAPI).

## Производительность (замерено на живом контуре)

Latency инференса на потоке 4 ТС (долгий стенд, 166 замеров, Docker):
**p50 2.5 мс, p95 2.8 мс, p99 3.1 мс, max 3.2 мс**
(`transport_gateway_prediction_latency_*` в `/metrics`; на свежем клоне
короткое окно даёт p99 ≈ 6.5 мс — из-за малого числа замеров, не из-за
деградации); очередь прогнозов 0; пересоединение WS с экспоненциальным
backoff; обрыв ML — деградация на baseline-правило без падения сервиса.
Холодный старт контейнеров: ml healthy ~15 с после сборки, backend — секунды.

## Архитектура (3 модуля)

* `backend/` — Go: приём/парсинг NDTP, map-matching координат на нитку
  (радиус 400 м), производные признаки (отклонение от плана, скорость на
  сегменте, простой), горизонт-менеджер 10–15 мин, инциденты, REST/WS.
* `ml/` — Python 3.12, FastAPI + CatBoost: регрессор `target_delay_s`
  (`model_v1online`) и классификатор P(опоздание) с топ-причинами
  (`model_v1online_late`); признаки — общий Go-код (`backend/internal/features`),
  офлайн-обучение и онлайн-инференс из одной матрицы.
* `dashboard/` — React + TS + MapLibre: маршруты, ТС, риск, инциденты,
  офлайн-фон карты без внешних тайлов.

Дополнительные возможности из ТЗ: **map-matching с NDTP-спецификой**,
**ансамбль регрессор+классификатор** (прогноз + вероятность + причина),
признаковая онтология с версионированием (`features/v1.yaml`).

## Сабмит Data Science

`submission.csv` (в корне) — 151 строка `sample_id;prediction` по validate.
Воспроизводство: `make ml-train ML_TAG=online && make ml-predict-validate &&
make submission -- --model ml/artifacts/predictions_validate.csv`
(без `--model` генератор откатывается на базовую подстановку — страховочный
артефакт). Аудит утечек/базелайнов: `make audit`; доказательство:
`scripts/oracle_audit.py`.

## Разработка без Docker

`make dev` — рабочий сеанс Zellij (backend :8080/:9201, Vite :5173, feed,
ML), `make help` — остальные цели (`build`, `test`, `lint`, `real-plan`,
`real-feed`, `ml-*`). Документация по устройству: `docs/how-it-works.md`,
решения — `docs/adr/`, соответствие ТЗ — `docs/tz-conformance.md`.
PyDoc по ML-коду (Sphinx/autodoc): `make docs` — HTML в
`docs/sphinx/build/html`, `make docs-serve` — то же на
http://localhost:8090 (нужен `ml/.venv` с зависимостями ML: `make ml-setup`).
REST-контракт: Swagger UI `:8080/swagger`, OpenAPI — `:8080/openapi.yaml`.
