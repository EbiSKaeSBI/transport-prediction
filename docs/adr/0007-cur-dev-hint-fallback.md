# 0007. `cur_dev_s` для validate: fallback на хинт организаторов

- Статус: принято
- Дата: 2026-09-25

## Контекст

ADR-0004 установил: раздаваемый `cur_dev_s` (хинт из `points.csv` /
`labels_*.csv`) в ~39–44 % меток опирается на факт, наступающий **после T**,
и конвейер намеренно считает собственный строгий `cur_dev_s` — отклонение
последней остановки, у которой и план, и факт прошли к T. Обучение v1
(#23) шло на строгих значениях.

При прогоне первой модели на validate обнаружилось следствие, которого
ADR-0004 не предвидел: **строгий `cur_dev_s` для validate-фолда
вычислительно недоступен**. `validate/schedule_plan.csv` не содержит колонку
`time_fact_begin` (в отличие от `train/schedule.csv` и `test/schedule.csv`),
а альтернативного источника фактов прохождения остановок в раздаче нет —
восстанавливать факт по трафику с точностью до секунды нельзя. Измерено:
`cur_dev_s = null` во **всех 142** Go-кадрах validate
(`ml/artifacts/features_validate.jsonl`), при 377/4099 null в train.
`cur_dev_s` — фича №1 по importance (~17/100), и v1 без неё деградировала
**ниже** baseline: MAE оракула 89.53 с против 88.58 с у чистого `cur_dev_s`.

## Решение

`predictor.dataset` принимает флаг `--cur-dev-fallback-hint` (по умолчанию
включён): если строгий `cur_dev_s` из Go-кадра null, значение берётся из
хинта раздачи (`labels_*.csv` для train/test, `validate/points.csv` для
validate). Источник фиксируется построчно в колонке `cur_dev_from_hint`
(Int8), которая **не входит** в фичи модели и попадает в метрики обучения
для прозрачности. Строки и ключи датасетов при этом не меняются;
проверено построчно: `flag=0 ⇒ значение равно Go-strict`, `flag=1 ⇒ равно
хинту`.

Эффект (оракул, 142 общие точки): v1b (fallback) — **MAE 58.20 с**,
score 0.463 против 89.53 (v1) и 88.58 (baseline); holdout `dataset_test` —
64.31 против 66.45. Ватерлайн этапа 3 — v1b.

## Последствия и границы

1. **Это не утечка в нашем смысле.** Хинт — официальный вход задачи для
   validate-фолда: организаторы сами раздают его в `points.csv` как
   «подсказку, известную в момент T». Мы не читаем закрытые факты — мы
   пользуемся тем, что нам дали на инференсе.
2. **Train/serve skew остаётся и переносится на этап 4.** В онлайне Go
   считает строгий `cur_dev_s`; обученная на смеси (91 % strict + 9 % hint
   в train) модель на живом потоке увидит строгую дистрибуцию. Для
   демо-контюра решение — или единая конвенция «given.cur_dev_s = строгий,
   где доступен», или отдельная калибровка; фиксируется как открытая задача
   этапа 4 (#6).
3. **Валидационная метрика перестаёт быть слепой к хинту.** Скоринг через
   локальный оракул теперь частично измеряет «модель + подсказка
   организаторов». Для честного питча это проговаривается открыто
   (критерий прозрачности раздела «Питч» в `docs/architecture.md`).
4. Аналогичный fallback сознательно **не** введён для `trend_5`/`momentum`
   и других факт-зависимых window-фич: хинта для них в раздаче нет, они
   остаются null на validate-фолде (решение #24).
