# 0002. Граница внешних зависимостей и транспорт Go ↔ Python по HTTP

- Статус: принято, уточнено [ADR 0008](0008-gateway-events-and-predictions-in-memory.md)
- Дата: 2026-09-25

## Контекст

[ADR 0001](0001-ndtp-parser-in-go.md) зафиксировал, что разбор протокола NDTP
реализуется на Go без кодогенерации и без внешних зависимостей. Формулировка
«в `go.mod` нет зависимостей, сборка воспроизводима» была продублирована в
`docs/architecture.md:417`, где весь backend назван «Go 1.24+, без внешних
зависимостей».

При этом проектная таблица в `docs/architecture.md:94` и `:192` требовала
сразу трёх вещей, каждая из которых вводит зависимость и кодогенерацию:

- `ogen` для генерации Go-сервера и клиента из OpenAPI;
- gRPC по `proto/ml.proto` с кодогенерацией для Go и Python;
- драйвер PostgreSQL для хранения прогнозов, инцидентов и метрик.

То есть проект сам себе противоречил: «ноль зависимостей» и «три
генератора кода» в одном репозитории. Противоречие нужно снять до того, как
оно размножится на пакеты.

Отдельно к решению по транспорту: `proto/ml.proto` уже написан и описывает
контракт `FeatureFrame → Prediction` корректно. Отказываться от схемы не
нужно — вопрос в том, чем её materializovat на проволосе.

## Рассмотренные варианты

### 1. Полный gRPC с кодогенерацией

`proto/ml.proto` компилируется через `protoc`/`buf` в Go-стабы и
Python-стабы, оба языка общаются по gRPC.

Отклонено. Требует в образе `protoc` и плагины, версии `google.golang.org/grpc`
и `protobuf` должны совпадать с версиями в `ml/uv.lock`, а регенерация
становится отдельной операцией в пайплайне с собственными точками отказа.
Выигрыша против HTTP на масштабе решения нет: ML-сервис обслуживает 30–56
транспортных средств, это десятки запросов в секунду.

Единственное реальное преимущество gRPC — строгий контракт. Оно достигается
дешевле: `proto/ml.proto` остаётся канонической схемой, а на проволосе идёт
JSON, который FastAPI генерирует в OpenAPI сам.

### 2. OpenAPI-first с генерацией через `ogen`

Схема OpenAPI пишется первой, из неё генерируется Go-сервер.

Отклонено как избыточное. `ogen` — крупная зависимость с собственным
генератором; рукописный `net/http` даёт те же 15 маршрутов из
`docs/architecture.md:255` без кодогенерации. Требование ТЗ — «Swagger
отвечает на пробный запрос» — выполняется проще: раздаём собственный
`openapi.yaml` и UI поверх него.

### 3. Граница: чистый stdlib на проводе, зависимости только в gateway

Принято.

## Решение

`backend/internal/ndtp`, `internal/ndtpserver` и `internal/telemetry`
остаются без единой внешней зависимости — это продолжает ADR 0001 и
оправдано: это критический путь приёма данных, который обязан собираться
и тестироваться без сети и без реестра модулей.

Взаимодействие Go и Python выполняется поверх HTTP+JSON (`net/http` +
`encoding/json` с обеих сторон). `proto/ml.proto` сохраняется как
каноническое описание контракта и как документация; при расхождении схемы
и JSON считается, что прав `proto/ml.proto`. Клиент Go проверяет список
имён признаков, полученный от ML, против `features/v1.yaml` и отказывается
работать при несовпадении.

Весь онлайн-контур — один бинарник `transportctl`; Python запускается
отдельным контейнером и общается с ним по сети.

## Последствия

Что становится лучше:

- пакеты протокола собираются и тестируются без сети и без реестра модулей:
  `go test ./...` для `internal/ndtp`, `internal/ndtpserver` и `internal/telemetry`
  идёт без прокси и без GOPROXY — это проверяемо в CI. Позже граница была
  уточнена [ADR 0008](0008-gateway-events-and-predictions-in-memory.md): ради
  ленты событий в `go.mod` появилась одна внешняя зависимость,
  `github.com/gorilla/websocket`;
- добавление HTTP-клиента к ML не тянет за собой версии, protoc и генерацию;
- OpenAPI не требует отдельного шага сборки: схема написана руками, встроена в
  бинарник и раздаётся как есть. Автоматической генерации нет — это следствие
  отказа от `ogen` выше, и плата за него состоит в том, что схему нужно
  поддерживать руками; маршруты сверяются с ней тестом, поэтому расхождение
  ловится, а не накапливается;
- контракт выражается дважды — в `proto/ml.proto` для людей и в JSON для
  машины, — и расхождение ловится проверкой имён признаков.

Что становится хуже:

- протокол не проверяется компилятором: опечатка в имени поля JSON даст
  нулевое значение, а не ошибку сборки. Поэтому проверка имён признаков
  обязательна и должна падать, а не предупреждать;
- для эмиссии NDTP-кадров (ACK, синтетический поток в `replay`) функции
  `checksum` и `swapBytes` из `crc.go` придётся продублировать: они
  неэкспортируемые, а ADR 0001 сознательно не расширяет API пакета `ndtp`.
  Дублирование — 30 строк, оно уже сделано в `ndtpserver_test.go:253`;
- «ноль зависимостей» теперь относится к пакетам протокола, а не ко всему
  модулю. Формулировку в `docs/architecture.md:417` нужно уточнить, иначе
  она снова введёт в заблуждение.
