# Соответствие ТЗ хакатона

Матрица built against `Предиктор_изменений_в_графике_движения_городского_транспорта.pdf`
(текст извлечён в `/tmp/opencode/tz.txt`). Дата проверки: 27 сентября 2026.

Замеры в разделе «Критерий 5» сняты с живого стенда: эмулятор NDTP на `:9201`,
backend на `:9201`/`:8080`, дашборд на `:5173`, три ТС в потоке.

Итого по основному этапу: **~16–18 из 26** баллов при текущем состоянии.
Основные точки роста — критерий 1 (MAE) и критерий 3 (Docker).

## Критерий 1. Точность ML-прогноза (0–6)

| Требование ТЗ | Реализация | Доказательство | Пробел |
|---------------|-----------|---------------|--------|
| Прогноз вероятности задержки 10–15 мин | `ml/src/predictor/late.py` — отдельная голова вероятности, `p_late` в ответе | `/metrics`: `transport_gateway_predictions_from_model_total` | — |
| Абсолютная ошибка времени отклонения | MAE-регрессия на дельту `target − cur_dev_s` | `docs/data-audit.md` | — |
| Баллы ≥ 0.70 (MAE ≤ 32.4 с) | не достигнуто | baseline `pred = cur_dev_s`: **MAE 88.72 с → score 0.18** | **валидного замера модели на validate нет** |

**Честная оценка:** заявленный README baseline 0.40 не воспроизводится на данных —
фактический baseline даёт 0.18, то есть 1 балл. Модель не отмерена на validate,
поэтому балл за критерий 1 сейчас не earned, а заявлен. Это главный риск сдачи:
до дедлайна 27 сентября 23:59 МСК нужен хотя бы один сабмит с измеренным MAE.

Пороги из `docs/architecture.md`: 6 баллов — MAE ≤ 32.4 с, 4 балла — MAE ≤ 54.1 с.

## Критерий 2. Горизонт 10–15 мин (0–4)

| Требование ТЗ | Реализация | Доказательство |
|---------------|-----------|---------------|
| Строго 10–15 мин до события | `MinHorizon=10m`, `MaxHorizon=15m` в расчёте цели | `backend/internal/horizon` |
| Нет «прогнозов задним числом» | цель выбирается только вперёд от текущего момента; `claim()` дедуплицирует по `(vehicle, target_stop_id)` | `docs/adr/0005-target-stop-rule.md` |
| Предполагаемое время опоздания и причина | карточка инцидента: `pred_delay_s`, `cause`, участок | live: 72 инцидента, `source=ml` |
| Горизонт на потоке, а не офлайн | backend+ML на живом эмуляторе, `p50 6.4 мс` | live `/metrics` |

Прогнозы стабильно формируются в окне T+10…15 мин, задним числом не
выдаются: цели выбираются сеткой вперёд, поэтому после наступления события
дубль не создаётся.

## Критерий 3. Три модуля + Docker (0–6)

| Требование ТЗ | Реализация | Состояние |
|---------------|-----------|-----------|
| Чётко выделены ML-ядро и Backend, не монолит | `ml/src/predictor/serve.py` (HTTP-сервис модели) + `backend/` (Go, API/оркестрация) + `dashboard/` (BI) | выполнено |
| API работает, Swagger отвечает | `GET /openapi.yaml` → 200, `GET /swagger` → 200 | выполнено |
| Backend принимает и парсит NDTP, сопоставляет с расписанием, считает признаки | `backend/internal/ndtp`, `features`, `mapmatch`; признаки: текущее отклонение, средняя скорость сегмента, время простоя | выполнено |
| Связь модулей end-to-end: поток → прогноз → дашборд | проверено вживую: 92 прогноза, 89 от модели, 0 от baseline-фолбэка | выполнено |
| **Упаковка в Docker-контейнеры** | **нет ни одного Dockerfile, нет compose** | **не выполнено** |
| **Поднимается по одной инструкции (README)** | **README в репозитории отсутствует** | **не выполнено** |

**Это жёсткое требование ТЗ, а не рекомендация.** Без Dockerfile и README
критерий 3 не закрывается: инструкция для жюри (обязательный артефакт № 3)
невыполнима. Требуется `docker-compose.yml` с тремя сервисами
(`ml-core`, `backend`, `dashboard`) плюс README с одной командой запуска.

## Критерий 5. Производительность и надёжность (0–4)

| Требование ТЗ | Замер | Оценка |
|---------------|-------|--------|
| Latency инференса < 1–2 с на поток ТС | **p50 6.4 мс, p95 9.0 мс, p99 21.1 мс, max 21.1 мс** (89 замеров) | выполнено с запасом |

| Деградация при обрывах связи без падения | эмулятор и клиенты отключались и возвращались, сервер продолжал работать; `readyz → true` после реконнекта | выполнено |
| Предсказуемый холодный старт Docker | измерить нельзя — Docker-образов нет | не проверено |

(`backend/internal/latency`).

## Дополнительные возможности

| Фича | Состояние |
|------|-----------|
| Map Matching с учётом специфики NDTP | **реализовано**: `backend/internal/mapmatch`, встроен в `features` |
| What-if анализ (выпуск доп. ТС) | **не реализовано** |
| Оптимизация инференса (ONNX/TensorRT/квантование) | **не реализовано**: модель — нативный CatBoost |
| Ансамбль (CatBoost + PyTorch/Transformer) | **не реализовано**: одна CatBoost-регрессия + голова вероятности |

**Расхождение с документацией:** `docs/architecture.md` (строка 17) заявляет
«ансамбль с PyTorch temporal encoder, экспорт в ONNX». В `ml/src/` этого нет —
`ml/src/predictor/composition.py` загружает `CatBoostRegressor`, torch и onnx в
собственном коде не используются. Заявление следует исправить, иначе
проверяющий код увидит расхождение между описанием и репозиторием.
